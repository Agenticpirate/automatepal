# AutomatePal demo recording plan

Target 2:30-2:45. Record only features that pass acceptance tests. No stock footage, copied logos, music or invented testimonials.

0:00-0:15: State the founder billing problem and clearly label the app a PayPal sandbox prototype.
0:15-0:55: Describe a fictional product. Show the AI-created catalog product and monthly plan, with actual returned IDs. Do not claim a subscription or revenue has occurred.
0:55-1:25: If tested, show order approval and completed capture using sandbox accounts. Otherwise omit it rather than imply completion.
1:25-1:50: Show an unsent fictional invoice draft. No real recipient email or real customer data.
1:50-2:20: Open the dashboard with visibly separate API-confirmed activity and fictional demo analytics. Ask the agent to explain the source and limits of its numbers.
2:20-2:40: Draft, do not send, a recovery email using fictional failed-payment examples. End on public repository and verified demo link.

End card: "Independent sandbox project. PayPal is a trademark of PayPal, Inc. Not affiliated with or endorsed by PayPal."

Before recording: finish hosted auth/storage, test each shot, use fictional names, remove secrets from screen, hide browser chrome if it contains private data, and confirm trademark permissions for any third-party material visible in footage. PayPal checkout footage contains PayPal marks, so review applicable permission before including it. A blanket no-logo claim would be inaccurate if third-party checkout footage is shown.
